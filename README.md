# 倍音解析エディタ（初版）

お手本の単音 WAV を聴きながら、どの倍音が強いか、いつ立ち上がり、どのくらい残るかを調べるツール。

## 使い方

```bash
cargo run --release -- path/to/sound.wav   # 引数なしでも起動可（開始画面で WAV・ライブ入力・サンプルを選ぶ）
cargo run --release --example gen_test_tones   # 試験音を test_tones/ に生成
cargo test --release                            # 完成確認の音例を自動チェック
```

アプリの音を取り込むときは `.app` として起動する。macOS は「システムオーディオ録音」の許可を、Info.plist に用途の説明を持つアプリにしか求めないため、`cargo run` で直接起動するとエラーにならずに無音だけが届く（画面に「無音のまま」と出る）。

```bash
./scripts/bundle_macos.sh --install   # .app を作って /Applications に置く（書き込めなければ ~/Applications）
```

置いた後は Finder・Launchpad・Spotlight から「HarmonicAnalyzer」で開ける。初回に「システムオーディオ録音」の許可を求められる。新しい版を入れるときは、アプリを終了してから同じコマンドをもう一度実行する（起動中なら止まって知らせる）。署名はアドホックなので、入れ直した後に許可を求め直されることがある。`--install` を付けなければ `target/release/HarmonicAnalyzer.app` を作るだけ（`open target/release/HarmonicAnalyzer.app` で起動）。

許可は「システム設定 > プライバシーとセキュリティ > 画面収録とシステムオーディオ録音」で後から変えられる。

アイコンは `assets/AppIcon.icns`。絵は `scripts/make_icon.swift` で描いていて、変えたときは `./scripts/make_icon.sh` で作り直す。

- **画面の構成**: 上の1行目にファイル・ライブ入力・再生・解析位置／再生位置・解析位置の「固定／再生に追従」・試聴の状態（「試聴: 550–770 Hz だけ」など）が常に出る。基音・窓長・表示・試聴フィルタの設定はその下に用途ごとにまとまり、幅が足りなければ折り返す（「設定を隠す」で畳める）。操作の一覧は「？ 操作方法」。
- **開始画面**: 音源を読み込む前は「WAV を開く」「ライブ入力」「サンプルで試す」が出る。サンプル（基音 220 Hz の4種）はアプリの中で作るので、配布用の `.app` でもファイル無しで開ける。
- **基音**: `A3`, `C#4`, `Bb2` などの音名、または `220` / `220 Hz`。A4 の基準とチューニング補正（±100 cent）で録音に合わせる。実際に使う周波数を常に表示する。「推定」を押すと、取り込んだ音（WAV・サンプル・ライブ入力の直近の音）から基音を推定し、最も近い音名とチューニング補正（cent）に設定する（YIN 法。音量のある区間の最大 40 か所で周期を求め、中央値を取る。範囲は 25 Hz〜4 kHz）。推定値と確からしさ（同じ周期が見つかった区間の割合）が横に出る。鐘のように倍音が整数倍でない音では、低めの値（共通の周期）が出ることがあるので、そのときは手で直す。
- **波形・スペクトログラム・倍音の時間変化**の3つは時間軸と解析位置（橙）・再生位置（緑）を共有する。どれかをクリックすると解析位置が移り、再生中ならそこから鳴り直す。橙と緑の縦線は近づくとカーソルが左右矢印になり、ドラッグで動かせる（シーク）。ドラッグ中は解析位置と各グラフが追従し、離したときに再生位置もそこへ移る。縦線から離れた所のドラッグは従来どおり表示の移動。Space で再生/停止。
- **倍音分布**（右）: 棒・一覧・凡例の名前をクリックすると、その倍音に注目する（詳細表示・「第k倍音の周り」の対象。表示の ON／OFF は変わらない）。注目中は時間変化のグラフでその倍音が太く手前に出て、ほかの線は半透明になる。同じ倍音をもう一度クリックすると注目を解除し、すべての線が元の濃さに戻る（起動時は注目なし）。時間変化のグラフに出すかは一覧のチェックで ON／OFF する。初期状態は第1〜第8倍音が ON、第9倍音以降は OFF。OFF にしても一覧に残る。「すべて OFF」「初期状態に戻す（1〜8）」で一括操作。範囲外の倍音はチェックできない。凡例は時間変化のグラフの上（グラフの外）に出る。解析位置の値は表と折れ線上の点で読め、棒と同じ値になる（同じ解析フレームを参照）。
- **倍音の範囲選択**: 倍音分布の棒の上を横にドラッグすると、その範囲にかかる倍音を選べる（確定前は白い帯と白枠で表示。見えている棒のうち範囲内のものだけが対象）。「選択のみ ON」（ほかは OFF）／「追加 ON」／「選択を OFF」で一覧のチェックへ反映する。Esc かキャンセルで取り消し。棒のクリックは従来どおり注目。
- **解析位置の固定／再生に追従**: 「再生に追従」では、再生中は再生位置のフレームを解析位置にする。グラフをクリック・ドラッグして解析位置を決めると「固定」に戻る。止めた位置はそのまま残り、最後まで再生した後に再生すると先頭から鳴る。
- **試聴フィルタ**: 「この帯域だけ聴く」と「この帯域を除く」を切り替えられる（スペクトログラム上ではそれぞれ水色・赤の帯）。範囲は Hz で入力するか、スペクトログラム上で Shift+ドラッグで指定する。帯の上下の線はそれぞれドラッグで動かせる（線の近くでカーソルが上下矢印になる）。「第k倍音の周り」で、注目中の倍音 ± 基音の半分に合わせられる。種類のメニューで「選択していない倍音をカット」にすると、倍音一覧でチェックした倍音の周り（k·f0 ± 幅、幅は基音に対する % で既定 ±25%）だけを残し、選んでいない倍音と倍音以外の成分（雑音や非整数倍の成分）はすべてカットする。チェックを変えると鳴る音もすぐ変わり、1本も選んでいなければ無音になる。残る帯はスペクトログラムに水色で出る。フィルタは再生音だけに掛かり、解析・グラフは元の音のまま。境界はなだらか（遷移幅は境界周波数の 3%、5〜100 Hz）で、境界ちょうどは −6 dB。
- **ライブ入力**: 「● ライブ入力…」で入力元のウィンドウを開き、入力元を選んでから「この入力元で開始」で始める。入力デバイス（マイク、オーディオインターフェイス、BlackHole などの仮想デバイス）の音を直近 5 秒ぶん保持し、約 70 ms ごとに解析し直して表示する（右端が現在、解析位置は常に最新のフレーム）。ウィンドウは「入力デバイス」と「アプリの音」のタブに分かれ、名前で絞り込める。入力は全チャンネルの平均。レベルメーターは直近のピーク（dBFS）。「■ ライブ停止」で、その時点の 5 秒がふつうの録音として残り、クリックで調べる・再生する・「WAV に保存…」で保存できる。ライブ中は再生と試聴フィルタは使えない（ハウリング防止）。初回は macOS のマイク使用許可を求められる。
- **アプリの音**（macOS 14.2 以降）: 入力元のウィンドウの「アプリの音」から、ブラウザなど特定のアプリが出している音だけを取り込める（● と「発音中」はいま音を出しているアプリで、先頭に並ぶ）。`.app` に属さないシステムの内部プロセスは「詳細」に畳んである。Core Audio のプロセスタップを使い、デジタルのまま受け取るので部屋の響きや雑音は入らない。アプリの音はそのままスピーカーからも聞こえる。ブラウザは別プロセス（Chrome なら Google Chrome Helper）から音を出すが、同じ `.app` の中のプロセスはまとめて取り込む。タブ単位では選べない（ブラウザ全体の音）。選んだ後に新しく音を出し始めたプロセスは入らないので、そのときは選び直す。Safari は音を WebKit の共通プロセスから出すため、一覧では「Safari」ではなく WebKit の名前で出ることがある。
- **AI解析用に書き出す**: ツールバーの「AI解析用に書き出す…」で、いま開いている音（全体、または指定した時間区間）と解析結果を 1 つの ZIP に保存する。AI や外部の解析プログラムに渡して「どの倍音が強いか」「どう減衰するか」「別の音と何が違うか」を数値で調べる用。書き出し画面で「音源・楽器」「奏法・エフェクト」「調べたいこと」を任意で書ける（未入力は不明として記録）。保存先を選ぶと裏で書き出し、進み具合・キャンセル・完了（「Finder で表示」）・失敗の理由が出る。書き出しは解析位置・倍音の ON／OFF・試聴フィルタを変えない。ライブ入力中は使えず、停止すると残った音を解析し直してから書き出せる。ZIP は一時ファイルに書いてから置き換えるので、失敗・キャンセルしても既存のファイルや壊れた ZIP は残らない。
  - `source.wav`: 試聴フィルタ適用前の音声。読み込み済みのサンプルを 32-bit float で保存（元のチャンネル数・順序・サンプリング周波数のまま。入力ファイルのバイト列のコピーではない）。ライブ入力の録音は保持しているモノラル。
  - **書き出す範囲**: 「音声全体」か「時間区間」（開始・終了を秒で。「← 解析位置」で解析位置を入れられる）。区間はサンプル単位で切り出し（終了は含まない）、同じ基音・同じ窓長で解析し直して、その音の一式を書く。一式の時刻 0 は区間の先頭で、`manifest.json` の `time_range` に開始・終了サンプル・`offset_s`（元の音源の時刻 = 時刻 + offset_s）を記録する。切り出しの端のフレームは `edge_padded` を付け直す。空・逆転・音源外の区間は書き出す前に知らせる。
  - **発音開始・持続区間**: 発音開始は「自動」（窓が音声に収まるフレームのうち、RMS が最大から 20 dB 以内に初めて入るフレーム。根拠を記録）か「指定」。持続区間は指定したときだけ使い、指定しなければ持続区間の代表レベルは出さない（推測で補わない）。キーを離した時刻は分からないので、リリース区間は扱わない。
  - `features.csv`: 1 行 = 1 倍音。最大レベルとその時刻（発音開始以降、ピークを検出した値）、持続区間の代表レベル（検出した値の中央値）、基音に対する相対レベルの中央値（持続区間があればその中、無ければ発音開始以降）、最大から −20 dB・−40 dB までの減衰時間（`reached` / 観測の終わりまで届かなければ `not_reached` / 閾値が −120 dB 以下なら `threshold_below_floor`）。値が無い欄は空欄で、理由の列がある。
  - `envelope.csv`: 1 行 = 1 フレーム（harmonics.csv と同じ時刻）。解析と同じ中心・長さの矩形窓での RMS とピーク（振幅 1.0 = 0 dB）、スペクトル重心（縮約前の線形振幅スペクトルを振幅で重み付け。無音は空欄）。
  - `harmonics.csv`: 1 行 = 1 フレームの 1 倍音。列は `frame_index,time_s,harmonic,target_hz,peak_hz,sampled_bin_hz,level_db,status,edge_padded,rel_h1_db,rel_h1_missing`。`rel_h1_db` は基音に対する相対レベル（基音とその倍音の両方でピークを検出したフレームだけ。無ければ `rel_h1_missing` に理由）。解析範囲内の全倍音・全フレーム（表示 OFF の倍音も含む。行数 = フレーム数 × 範囲内の倍音数）。`status` は `detected_peak`（局所ピークを検出。楽器由来とは限らない）／`sampled_target_bin`（検出できず目標に最も近いビンの値）／`below_floor`（−120 dB 以下で真の値は不明）。`peak_hz` は検出したときだけ、`sampled_bin_hz` は検出できなかったときだけ値がある。`edge_padded` は窓が音声の端をまたいでゼロで埋めたフレーム。
  - `manifest.json`: `schema_version`（いまは 1.1.0）、音源情報、解析に使った基音と入力（音名・A4・補正）、推定値（推定方法と「確からしさ」の定義。この音で推定したものでなければ null）、窓・hop・FFT・時刻の定義・正規化と dB の基準・ピーク探索の幅と丸め、解析できる最大の倍音、表示状態（ON の倍音・注目・解析位置・表示範囲・表示下限）、試聴フィルタ、CSV の列の定義、利用者の入力、制約。不明な値は null（CSV では空欄）で、NaN・Infinity は出さない。
  - `overview.png`: 波形（解析に使ったモノラル）・スペクトログラム（最大値縮約、カラーバー付き）・表示 ON の倍音の時間変化（凡例・解析位置・端部の網掛け付き）。ウィンドウ幅に関係なく 1600 px 幅で描く。すべて OFF のときは「表示倍音なし」と描く。
  - `summary.txt`: 音源、利用者の入力、解析条件の要点、ファイルの読み方、倍音ごとの最大レベルと時刻（窓が音声に収まるフレームで、ピークを検出した値だけを集計）、解析位置の値、表示と試聴の状態、書き出した範囲、特徴量（発音開始・持続区間・倍音ごとの代表値・基音比・減衰時間・RMS の最大・スペクトル重心の中央値）、解釈の制約。
  - AI に渡すときの質問の例: 「harmonics.csv から第1〜第8倍音の減衰の速さを比べて、FM シンセで近づけるための目安を教えて」「2 つの ZIP の倍音の相対レベルの違いをまとめて」「overview.png で倍音以外の成分がどこにあるか見て」。
- **実測ピーク**: 倍音一覧の「実測ピーク」は、対象周波数 ± 基音の 10% に局所ピークがあったときだけ周波数を出し、無ければ「未検出」と出す（そのときのレベルは対象に最も近い FFT ビンの値）。
- **レベル基準**: 0 dB = 振幅 1.0（フルスケール）の正弦波。録音全体・全倍音で共通。下限は −120 dB（無音はこの値で、異常値は出ない）。
- **範囲外**: 倍音の周波数がサンプルレートの半分以上なら「範囲外」とし、棒グラフ上では灰色の網掛け、読み取り欄では「範囲外」と表示する。範囲内で微弱な倍音は「≤ −120 dB（下限）」と表示する。

## 解析方法

- 4項 Blackman-Harris 窓（サイドローブ −92 dB）＋ 2倍ゼロ詰めの STFT。
- 窓長は既定で「基音の8周期以上を含む2のべき乗」（220 Hz/48 kHz なら 2048 = 42.7 ms）。手動で 512〜16384 を選べる。ホップは窓長の 1/8（64〜512 サンプル）。
- 第k倍音は k·f0 ± 10%·f0 の範囲でピークを探し、対数振幅の放物線補間で FFT ビンの間にある周波数の振幅を求める。範囲内に極大が無い場合（隣の成分の裾など）は k·f0 のビンの値を使う。

## 初版で決めた前提

| 項目 | 決定 |
|---|---|
| 対象 OS・形態 | macOS の単体アプリ（egui/eframe なので Windows/Linux でもビルド可能。日本語フォントは OS のものを読み込む） |
| WAV | PCM 8/16/24/32 bit 整数、32 bit 浮動小数点。チャンネル数は任意。解析は全チャンネルの平均、再生は元のチャンネルで行う |
| 音域 | 基音 10 Hz〜fs/2。解析する倍音は最大 512 本 |
| 時間分解能 | 上記の窓長・ホップ（自動 / 手動切替） |
| ライブラリ | eframe/egui + egui_plot（GUI）、cpal（再生）、hound（WAV）、realfft（FFT）、rfd（ファイル選択） |

## 開発用

`HA_SCREENSHOT=out.png HA_CURSOR=1.0 HA_SELECT=1,3 HA_FILTER=600-900 harmonic_analyzer file.wav` で、解析位置・表示する倍音・試聴フィルタ（`600-900:cut` で除去、`harm` や `harm:10` で選択していない倍音をカット）を指定した画面を PNG 保存して終了する。`HA_WIDTH=1070`（ウィンドウ幅）、`HA_SAMPLE=3`（サンプルを開く）、`HA_PICK=7-9`（倍音分布の横軸で範囲選択し、確定前の状態にする）、`HA_SOURCES=1` / `HA_SOURCES=app`（入力元のウィンドウ）、`HA_HELP=1`（操作方法）、`HA_FOCUS=3`（注目する倍音）、`HA_ESTIMATE=1`（基音を推定）、`HA_EXPORT=out.zip`（その状態で AI 解析用に書き出し、結果を標準エラーに出す。`HA_EXPORT_QUESTION=…` で質問欄、`HA_EXPORT_RANGE=0.5-1.5` で時間区間、`HA_EXPORT_SUSTAIN=0.6-1.4` で持続区間、`HA_EXPORT_ONSET=0.05` で発音開始。いずれも元の音源の秒）、`HA_EXPORT_DIALOG=1`（書き出し画面）も使える。`HA_LIVE=1` を付けるとライブ入力を始め、約 2 秒後に保存する（`HA_LIVE=app:アプリ名` でアプリの音）。
